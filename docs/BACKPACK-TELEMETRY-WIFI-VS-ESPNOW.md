# ELRS Backpack Telemetry: Wi-Fi vs ESP-NOW

У приложения два способа получения телеметрии с ELRS TX-бэкпака:

- **Wi-Fi — по умолчанию.** Не требует дополнительного железа, кабеля и OTG. Подходит, чтобы быстро начать и проверить телеметрию на стенде или в поле.
- **ESP-NOW через USB-приемник — рекомендуемый.** Меньше засоряет радиоэфир: нет Wi-Fi AP/beacons/DHCP и трафика телефона в 2.4 ГГц. Требует ESP32-C3 с native USB, OTG-адаптер и кабель.

Оба способа дают одни и те же CRSF-кадры и одинаково отображаются в приложении. Переключение — в настройках по шестерёнке в шапке.

## Коротко

- **Нужно начать без покупок:** Wi-Fi. Бэкпак поднимает точку доступа или подключается к вашей сети, телефон слушает UDP `14550`.
- **Нужен минимальный вклад в эфир:** ESP-NOW + USB-приемник. Бэкпак шлёт короткие ESP-NOW-кадры, приемник ESP-NOW отдаёт CRSF по USB, телефон может оставаться без Wi-Fi.
- **ELRS 900 МГц + дальние полёты:** Wi-Fi-бэкпак работает на 2.4 ГГц, линк — на 900 МГц; общего диапазона нет, влияние Wi-Fi на линк минимально. Это хороший сценарий для варианта по умолчанию.
- **ELRS 2.4 ГГц, высокая телеметрия или загруженный эфир:** ESP-NOW предпочтительнее — меньше airtime и нет постоянного Wi-Fi-фона.
- **Нужен нативный MAVLink/QGC:** только Wi-Fi-путь с `Link Mode = MAVLink`. USB-приемник ESP-NOW отдаёт CRSF и для нативного MAVLink не подходит; приложение поддерживает MAVLink в источнике «Сеть».
- **Нет OTG/USB host на телефоне:** остаётся Wi-Fi.

## 1. Диапазоны: кто с кем делит эфир

| Линк дрон↔аппаратура | Радио бэкпака | Пересечение | Что это значит |
|---|---|---|---|
| 900 МГц | 2.4 ГГц Wi-Fi/ESP-NOW | Нет общего диапазона | Wi-Fi/ESP-NOW почти не мешают линку; возможно только внеполосное блокирование при очень близких антеннах |
| 2.4 ГГц | 2.4 ГГц Wi-Fi/ESP-NOW | Один диапазон | Wi-Fi/ESP-NOW могут создавать коллизии и поднимать шум; влияние зависит от airtime, канала, антенн и трафика |

Практический вывод: **Wi-Fi — разумный вариант по умолчанию, особенно на 900 МГц; ESP-NOW — рекомендуемый путь, когда важен минимальный airtime и чистота эфира.**

## 2. Wi-Fi-телеметрия бэкпака

Как работает:

- бэкпак поднимает Wi-Fi AP или подключается к сети как STA;
- телефон/ПК подключается к AP или находится в той же сети;
- телеметрия идёт UDP-пакетами (по умолчанию `14550`);
- в Wi-Fi-режиме бэкпак также может продолжать отправлять ESP-NOW-телеметрию
  (для VRX-бэкпака/очков), то есть радио работает ещё активнее.

Плюсы:

- не нужен приемник ESP-NOW, кабель и OTG;
- работает с Android-приложением и `tlm_viewer.py` без дополнительного железа;
- удобно на стенде и для быстрой проверки;
- при 900 МГц-линке влияние на линк минимально.

Минусы:

- Wi-Fi AP/STA добавляет beacons, management, DHCP/ARP;
- телефон рядом с аппаратурой тоже передаёт в 2.4 ГГц;
- при 2.4 ГГц-линке возможны коллизии с FHSS;
- при высокой телеметрии и/или загруженном эфире LQ может проседать;
- в поле надо поднимать AP/сеть, следить за каналом и клиентами.

## 3. ESP-NOW и USB-приемник

Как работает:

- бэкпак переводится в `Telemetry → ESP-NOW`;
- телеметрия идёт короткими ESP-NOW-кадрами;
- USB-приемник ESP-NOW на ESP32-C3 принимает ESP-NOW и отдаёт CRSF в телефон по native USB CDC;
- телефон может оставаться без Wi-Fi, интернет для карты — через мобильные данные.

Плюсы:

- нет Wi-Fi AP/beacons/DHCP и трафика телефона в 2.4 ГГц;
- меньше средний airtime у бэкпака — меньше засорение эфира;
- телефон может быть без Wi-Fi;
- предсказуемый USB serial, без настроек сети;
- хорошо подходит для 2.4 ГГц-линка, высокой телеметрии и дальних полётов
  в пределах 2.4 ГГц.

Минусы:

- нужен приемник ESP-NOW, OTG и кабель;
- телефон не заряжается одновременно без хаба;
- приемник ESP-NOW сам является ещё одним 2.4 ГГц-радио (хотя с низким duty cycle);
- нативный MAVLink так не получить: по ESP-NOW идёт CRSF.

## 4. Что именно страдает в линке

- **Основная жертва — приёмник TX-модуля** (downlink/телеметрия), потому что
  радио бэкпака физически рядом.
- **Uplink управления** страдает меньше: его передаёт TX-модуль, а бэкпак —
  отдельное радио.
- **RX дрона** может слышать бэкпак только вблизи: стенд, взлёт/посадка.
- **Чем больше телеметрии**, тем больше airtime: 10 GPS/с, высокий TLM ratio,
  MAVLink-поток — всё это увеличивает нагрузку на 2.4 ГГц в обоих режимах.
- **Wi-Fi-режим** добавляет фиксированную нагрузку (beacons/management) даже без
  активного трафика; **ESP-NOW** — только короткие кадры телеметрии и ACK.

## 5. Таблица сценариев

| Задача | Линк | Рекомендуемый путь | Почему |
|---|---|---|---|
| Быстрый старт без покупок | любой | Wi-Fi | Не нужно дополнительное железо |
| Дальний полёт | 900 МГц | Wi-Fi | Разные диапазоны; влияние на линк минимально |
| Дальний полёт | 2.4 ГГц | ESP-NOW + USB-приемник | Меньше same-band airtime, телефон без Wi-Fi |
| Фристайл близко | 2.4 ГГц | Wi-Fi допустим при низкой телеметрии | Близко и мало кадров; следить за LQ |
| Фристайл + 10 GPS/с | 2.4 ГГц | ESP-NOW + USB-приемник | Высокая телеметрия; Wi-Fi добавляет лишний airtime |
| QGC / нативный MAVLink | 900 МГц | Wi-Fi + `Link Mode = MAVLink` | MAVLink идёт только по Wi-Fi; 900 МГц не пересекается с 2.4 |
| QGC / нативный MAVLink | 2.4 ГГц | Wi-Fi + MAVLink как компромисс | Same-band нагрузка; приемник ESP-NOW отдаёт CRSF |
| Очки/VRX-бэкпак | 2.4 ГГц | ESP-NOW | Wi-Fi добавляет лишний airtime |
| Поле без Wi-Fi | любой | USB-приемник ESP-NOW | Не нужна сеть/AP |
| Телефон без OTG | любой | Wi-Fi | USB-приемник ESP-NOW физически невозможен |

## 6. Когда Wi-Fi — вариант по умолчанию

- Нужно начать без покупки приемника ESP-NOW, OTG и кабеля.
- ELRS-линк **900 МГц**, особенно дальние полёты.
- ELRS 2.4 ГГц, но полёты **близко**, телеметрия низкочастотная, антенны
  разнесены, эфир не забит.
- Нужен **нативный MAVLink** от FC/QGC: бэкпак в `Link Mode = MAVLink` и
  `Telemetry = WiFi`.
- Нужно быстро посмотреть телеметрию на стенде или с ноутбука.

## 7. Когда рекомендуем ESP-NOW + USB-приемник

- Нужно **меньше засорять радиоэфир**: убрать Wi-Fi AP/beacons и трафик телефона.
- 2.4 ГГц-линк и нужна телеметрия на дальности или с высокой частотой.
- 10 GPS/с, высокий TLM ratio, частые кадры attitude/battery.
- Хочется предсказуемый USB serial без сети и DHCP.
- Бэкпак должен оставаться в ESP-NOW (например, для VRX/очков).
- Поле без Wi-Fi-инфраструктуры.

Когда ESP-NOW **не нужен**:

- нужен именно нативный MAVLink, а не CRSF-путь;
- нет OTG/USB host на телефоне;
- не готовы к кабелю, OTG и отдельному приемнику ESP-NOW;
- Wi-Fi уже стабильно работает на вашем сценарии.

## 8. OTG и ESP32-C3: что именно нужно

Ключевое: **ESP32-C3 не работает USB-хостом.** В схеме «приемник ESP-NOW в телефоне»
хостом выступает телефон, а C3 — USB-устройство. Поэтому OTG нужен **телефону**,
а не C3.

| Сценарий | Нужен OTG? | Кто хост | Что видит телефон | Комментарий |
|---|---|---|---|---|
| Телефон + ESP32-C3 Super Mini (native USB) | Да | Телефон | CDC-ACM | Рекомендуемый вариант; нужен OTG-адаптер и data-кабель |
| Телефон без USB host/OTG | — | — | — | USB-приемник ESP-NOW невозможен; только Wi-Fi |
| Телефон + OTG + powered hub | Да | Телефон/хаб | CDC-ACM | Позволяет заряжать телефон; нужен качественный хаб |

Что это значит для покупки:

- **ESP32-C3 Super Mini** — компактный и дешёвый вариант с native USB.
- **OTG-адаптер** обязателен: USB-C→USB-A female + data-кабель к плате,
  либо готовый OTG data-кабель.
- **Charge-only кабели не подходят** — нужен data-кабель.
- **Одновременная зарядка** — только через powered USB-C hub; не все телефоны
  и хабы это умеют.

## 9. Список покупок для USB-приемника ESP-NOW

| Что | Зачем | Примечание |
|---|---|---|
| ESP32-C3 Super Mini | Приемник ESP-NOW | Native USB CDC, прошивка `esp32-c3-usb` |
| USB-C→USB-A female OTG-адаптер или OTG data-кабель | Телефон как хост | Проверить поддержку USB host |
| Data-кабель к приемнику ESP-NOW | Подключение | Не charge-only |
| Android-телефон с OTG, Android 7+ | Приёмник | Нужен USB host |
| Powered USB-C hub (опционально) | Зарядка + приемник ESP-NOW | Не все телефоны/хабы поддерживают |
| Корпус/крепление (опционально) | Эксплуатация | Держать антенну приемника ESP-NOW подальше от антенны TX |

Для прошивки нужен ПК с PlatformIO или web-flasher. Android-приложение
собирается из каталога `android/` этого репозитория.

## 10. MAVLink / QGC

- **Нативный MAVLink** с бэкпака возможен только по Wi-Fi:
  `Link Mode = MAVLink` + `Backpack → Telemetry → WiFi`. FC должен отдавать
  MAVLink (Betaflight 2025.12.2, ArduPilot/PX4).
- На 900 МГц это хороший вариант: MAVLink идёт по 2.4 ГГц Wi-Fi, линк — на
  900 МГц, диапазоны не пересекаются.
- На 2.4 ГГц это компромисс: Wi-Fi-телеметрия делит диапазон с линком; для
  дальних полётов лучше 900 МГц + Wi-Fi/MAVLink.
- **USB-приемник ESP-NOW отдаёт CRSF**, а не нативный MAVLink. Приложение
  поддерживает MAVLink в источнике «Сеть»; для QGC нужен Wi-Fi-путь или
  отдельный MAVLink-мост/расширение прошивки.
- Для 10 GPS/с в MAVLink-Wi-Fi: `mavlink_pos_rate = 10`; подробности — в
  [ELRS-RATE-TELEMETRY-CHEATSHEET.md](ELRS-RATE-TELEMETRY-CHEATSHEET.md).

## 11. Чеклист перед полётом

- Разнести антенны бэкпака/телефона/приемника ESP-NOW и антенну TX-модуля.
- Для 2.4 ГГц-линка проверить LQ/RSSI/SNR на стенде в обоих режимах.
- В Wi-Fi-режиме убрать лишний трафик телефона, не ставить телефон на TX.
- При 2.4 ГГц и высокой телеметрии предпочесть приемник ESP-NOW.
- Для 900 МГц дальних полётов Wi-Fi обычно безопасен.
- Проверить, что бэкпак действительно в нужном режиме:
  `Telemetry → WiFi` или `Telemetry → ESP-NOW`.
- Для приемника ESP-NOW: `Link Mode = Normal`, `Telemetry → ESP-NOW`, та же binding
  phrase/UID, что у бэкпака.
- Не летать с просевшим LQ; сначала стенд/близкая дистанция.

## 12. Ограничения

- Выводы без измерений: реальное влияние зависит от конкретного бэкпака,
  TX-модуля, антенн, корпуса, канала и загруженности 2.4 ГГц.
- Wi-Fi-канал, мощность и поведение AP/STA зависят от прошивки бэкпака.
- Телефон, его Wi-Fi и положение относительно аппаратуры — важный фактор.
- ELRS 2.4 ГГц использует FHSS; Wi-Fi/ESP-NOW на фиксированном канале могут
  пересекаться с частью хопов.
- Нативный MAVLink и CRSF-путь — разные сценарии; не смешивать.
