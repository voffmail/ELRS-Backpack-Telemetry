# ELRS Backpack Telemetry — технический справочник

Технические детали для разработчиков и продвинутых пользователей. Установка и краткий старт — в [README](../README.md); сборка, toolchain, CI и релизы — в [DEVELOP.md](../DEVELOP.md).

## Два способа получения телеметрии

| Способ | Статус | Что нужно | Как включается |
|---|---|---|---|
| Wi-Fi (UDP) | По умолчанию | Wi-Fi-бэкпак, общая сеть | `Backpack → Telemetry → WiFi`, приложение слушает UDP-порт |
| ESP-NOW по USB | Рекомендуется | ESP32-C3 с native USB, OTG-адаптер и data-кабель | `Backpack → Telemetry → ESP-NOW`, приемник ESP-NOW в USB, источник в настройках |

Wi-Fi не требует дополнительного железа — с него проще начать. ESP-NOW
рекомендуется из-за меньшего засорения радиоэфира: нет Wi-Fi AP/beacons,
DHCP и трафика телефона в 2.4 ГГц. Подробное сравнение —
[BACKPACK-TELEMETRY-WIFI-VS-ESPNOW.md](BACKPACK-TELEMETRY-WIFI-VS-ESPNOW.md).

Переключение источника — в настройках по шестерёнке в шапке приложения:
**«Сеть»** или **«ESP-NOW по USB»**. Общие настройки (треки, энергосбережение,
разрешения) видны в обоих режимах.

## Протоколы: CRSF и MAVLink

В источнике **«Сеть»** протокол определяется автоматически по первому валидному
кадру:

- CRSF — MSP-обёртка `$X<` или адреса `0xC8/0xEA/0xEE`, CRC8;
- MAVLink v1/v2 — `0xFE/0xFD`, CRC16 + `CRC_EXTRA`.

Ручной настройки протокола нет. При смене протокола (например, ELRS
`Link Mode = MAVLink` → `Normal`) приложение закрывает старую сессию,
останавливает и сохраняет текущий трек, затем начинает новую сессию.
Порог переключения — около 500 мс молчания старого протокола и 2–3 валидных
датаграммы нового.

MAVLink поддерживается в Wi-Fi/UDP. USB-приемник ESP-NOW остаётся
CRSF-путём: backpack в MAVLink-режиме не отправляет MAVLink в ESP-NOW.

В MAVLink-режиме доступны GPS, карта, трек, attitude, battery, flight mode,
RSSI % и счётчики сообщений. Недоступны ELRS-метрики LQ, SNR, TX power,
antenna, band, packet rate и Range: backpack не получает CRSF `0x14` в этом
режиме. `link_up` для MAVLink считается по свежести `HEARTBEAT`.

## Что показывается

| Карточка | Данные |
|---|---|
| Линк | Uplink/Downlink LQ, RSSI, SNR, TX power, активная антенна, диапазон, пакетрейт, Range |
| Батарея | Напряжение, ток, израсходованная ёмкость, остаток % |
| GPS | Координаты, высота, скорость, курс, 3D/2D/нет фикса, HDOP, число спутников, расширенные поля `0x06`, QR с geo-координатами |
| Полёт | Режим полёта, барометрическая высота, варио, GPS-время, устройство |
| Ориентация | Pitch / roll / yaw и авиагоризонт |
| Приём | Пакетов/с, всего пакетов, возраст данных, типы CRSF-кадров с описаниями |

Поддерживаемые кадры: `0x02` GPS, `0x03` GPS Time, `0x06` GPS Extended, `0x07` Vario, `0x08` Battery, `0x09` Baro Altitude, `0x14` Link Statistics, `0x1E` Attitude, `0x21` Flight Mode, `0x29` Device Info. Остальные типы попадают в таблицу кадров как `Unknown`, а их последние payload доступны в API (`unknown`).

## GPS, фикс и QR

3D-фикс определяется по `fix_type` из `0x06`, если он есть, иначе по числу спутников (`≥4`). 2D — `≥3`. `flight_mode` для определения фикса не используется.

- **Android-приложение:** `gps_last` обновляется только на 3D-фиксе. Пока идёт запись, сохраняется каждый GPS-кадр `0x02` вместе с его `fix_type` — включая 2D и отсутствие фикса.
- **Python-вьюер:** `gps_last` обновляется на 2D/3D-фиксе; в трек пишутся только кадры с 3D-фиксом.

QR строится по последним известным координатам (`gps_last`). Нажатие на QR открывает точку в приложении навигации: в Android-приложении — через системный `geo:` intent, в браузере — через обработчик `geo:` ОС.

## Карта

Вкладка «Карта» показывает положение дрона на **MapLibre GL JS** с гибридной подложкой:
спутник + дороги и подписи OpenStreetMap/OpenFreeMap. Ключ и регистрация не нужны.

Прямая ссылка на вкладку: `http://localhost:8080/?tab=map`.

На карте: маркер дрона, координаты/спутники/скорость, переключатель **Follow** (автоцентрирование) и кнопка **Center**. Если текущего GPS-фикса нет, маркер показывается на **последней известной** точке и приглушается; если координат ещё не было — маркер скрыт и выводится «Нет GPS-фикса».

Слои:
- **Esri World Imagery** — основной спутниковый слой высокого разрешения, без ключа;
- **Sentinel-2 cloudless** (EOX) — резервный слой 10 м на случай недоступности Esri; EOxCloudless 2025 — CC BY-NC-SA 4.0, только некоммерческое использование;
- **OpenFreeMap Liberty** — векторные дороги, границы и подписи; непрозрачные landuse/fill-слои убраны, чтобы был виден спутник.

Атрибуция OpenStreetMap/OpenFreeMap, Esri и EOX выводится на карте. Esri — американский сервис, поэтому доступность и условия использования из РФ не гарантированы; при его недоступности останется Sentinel-2. Векторные подписи и дороги при этом сохраняются.

### Офлайн-карты (Android)

В настройках Android-приложения есть раздел **«Карта»**:

- **Скачать видимую область** — кнопка на карте доступна при зуме **z10+**.
  Скачивается текущий bbox карты + **5% padding** на максимальном офлайн-зуме
  **z14**. Лимит — **45 МБ** на вектор + спутник (50 МБ с запасом 10%).
  Никакого диалога радиуса/зума нет: только прогресс и отмена.
  Вектор — OpenFreeMap, спутник — Sentinel-2 (EOxCloudless 2025,
  CC BY-NC-SA 4.0, non-commercial) включается всегда.
  Если область не помещается в бюджет, кнопка скрыта.
- **Импорт .pmtiles** — готовый региональный архив (OpenFreeMap/OpenMapTiles).
- **Режим карты**: `Онлайн`, `Авто` или `Оффлайн`. В режиме «Оффлайн»
  приложение не делает внешних запросов карты. В «Авто» офлайн используется
  только если пак покрывает текущую точку, иначе загружается онлайн-карта.
- Список паков, занятое место и кнопка **«Очистить оффлайн карты»**.

Офлайн-режим использует локальный стиль `web/static/style-offline.json` и локальные
`glyphs/`/`sprite/`. Если в паке есть `satellite`, стиль становится гибридным:
спутник Sentinel-2 снизу + дороги/подписи сверху. Паки лежат в `filesDir/offline`
(скачанные области) и `filesDir/tiles` (PMTiles).

На карте есть иконка загрузки рядом с выбором режима — она сразу скачивает
видимую область и показывает прогресс.

HTTP API (Android):

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/offline` | список паков, прогресс, свободное место |
| `POST` | `/api/offline/download` | скачать bbox: `{bbox:[minLon,minLat,maxLon,maxLat],maxzoom,satellite}` |
| `POST` | `/api/offline/cancel` | отменить скачивание |
| `DELETE` | `/api/offline/packs/<id>` | удалить пак |
| `GET` | `/offline/<id>/{z}/{x}/{y}.pbf` | векторные тайлы области |
| `GET` | `/offline/<id>/sat/{z}/{x}/{y}.jpg` | спутниковые тайлы Sentinel-2 |
| `GET` | `/tiles/<name>.pmtiles` | импортированный PMTiles (HTTP Range) |

Python-вьюер пока остаётся онлайн-режимом; общий код карты находится в
`web/static/elrs-map.js`, стиль и ресурсы — в `web/static/`.

## Запись и воспроизведение трека

На вкладке «Карта» есть панель трека. Она свёрнута по умолчанию — раскрывается кликом по заголовку «Трек».

- **Запись / Стоп** — кнопка старта недоступна без текущего GPS-фикса (2D/3D); в Android-приложении пишет каждый GPS-кадр `0x02`, пока запись активна; в Python-вьюере точки пишутся только при 3D-фиксе. Остановить активную запись можно всегда.
- **Автозапись** (Android) — начать новый трек при появлении 3D-фикса. По умолчанию выключена.
- **Авто-стоп** (Android) — остановить запись при потере телеметрии. По умолчанию 10 с; `0` — никогда.
- **Хранить треков** (Android) — при сохранении нового трека старые удаляются, пока их число не станет равно лимиту. По умолчанию 10; пусто — без ограничения; `0` недопустим.
- Список сохранённых треков; выбор в списке сразу загружает трек. Кнопки **Удалить**, **GPX**, **KML** показываются, когда трек выбран.
- **GPX/KML** в Android-приложении сохраняются в `Download/ELRS Backpack Telemetry/` и сопровождаются сообщением с путём.
- Воспроизведение: **Играть / Пауза**, перемотка, скорость `1× / 2× / 5× / 10×` — появляется после загрузки трека.
- При включённом **Follow** карта следует за маркером воспроизведения.
- После остановки записи трек автоматически загружается для просмотра.
- Папку хранения можно сменить в настройках Android-приложения; существующие треки копируются в новую папку. При смене папки запись нужно остановить.

Частота точек записи равна частоте GPS-кадров `0x02` в ELRS-потоке: Android-приложение пишет каждый пришедший кадр без прореживания, Python-вьюер — только кадры с 3D-фиксом. В тестовом захвате это ~0.2–0.3 Гц (кадр раз в 3–5 с), что ограничено telemetry ratio/расписанием сенсоров FC, а не вьюером.

Треки сохраняются в `tracks/<id>.json`, где `id` — `track_YYYYmmdd_HHMMSS`.
Текущий формат — v2; старые треки без `version` читаются как CRSF v1.

```json
{"version": 2, "protocols": ["crsf"],
 "points": [
   {"t": 1.287, "lat": 61.2538884, "lon": 73.1888693, "alt": 140.0,
    "speed": 7.6, "heading": 107.7, "sats": 4,
    "fix_type": 3, "fix_type_computed": false,
    "protocol": "crsf", "session_id": "session_20261110_120000",
    "telemetry": {"gps": {"lat": 61.2538884},
                  "link": {"lq": 100}, "battery": {"voltage": 23.8}},
    "data": {}}
 ]}
```

`telemetry` — нормализованный снимок для UI, `data` — расширяемое место для
протокол-специфичных и будущих полей (например, `data.mavlink`). Смена
протокола останавливает и сохраняет текущий трек, поэтому трек получается
однопротокольным. `t` — секунды от начала записи; длительность — время
последней точки.

### HTTP API треков и настроек

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/record/start` | начать запись |
| `POST` | `/api/record/stop` | остановить и сохранить трек |
| `GET` | `/api/record?since=N` | состояние записи и новые точки начиная с индекса N |
| `GET` | `/api/tracks` | список сохранённых треков |
| `GET` | `/api/tracks/<id>` | точки трека |
| `DELETE` | `/api/tracks/<id>` | удалить трек |
| `GET` | `/api/settings` | источник (`source`), UDP-порт, статус USB, папка треков, статус записи, таймаут энергосбережения, авто-запись/авто-стоп, лимит треков |
| `POST` | `/api/settings` | изменить настройки, например `{"source": "usb"}` или `{"keep_tracks": 10}` (`null` — без ограничения, `0` недопустим) |
| `GET` | `/api/dongle` | конфиг USB-приемника ESP-NOW: state, UID, phrase, версия прошивки, режим UID |
| `POST` | `/api/dongle` | команды приемнику ESP-NOW: `set_phrase`, `set_uid`, `reset`, `ping` |

`/api/settings` и `/api/dongle` реализованы в Android-приложении. Примеры:

```bash
curl -s -X POST -H 'Content-Type: application/json' \
  -d '{"source":"usb"}' http://127.0.0.1:8080/api/settings
curl -s -X POST -H 'Content-Type: application/json' \
  -d '{"action":"set_phrase","phrase":"my-phrase"}' http://127.0.0.1:8080/api/dongle
curl -s -X POST -H 'Content-Type: application/json' \
  -d '{"action":"set_uid","uid":"AA:BB:CC:DD:EE:FE"}' http://127.0.0.1:8080/api/dongle
```

`source` — `network` (Wi-Fi/UDP, по умолчанию) или `usb` (приемник ESP-NOW).
В режиме `usb` UDP-порт сохраняется, но слушатель не запускается.

## Диапазон, пакетрейт и Range

Диапазон и пакетрейт определяются по полю `rf_mode` из `0x14` для ELRS 4.x:

| `rf_mode` | Диапазон |
|---|---|
| `0…11` | 900 MHz |
| `20…36` | 2.4 GHz |
| `100…101` | Dual |

Основные пороги чувствительности для расчёта Range (ELRS 4.x):

| Диапазон | Пакетрейт → порог, dBm |
|---|---|
| 900 MHz | 25 Hz −123, 50 Hz −120, 100 Hz −117, 100 Hz/8ch −112, 200 Hz −112, 50 Hz DVDA −112 |
| 2.4 GHz | 50 Hz −115, 150 Hz −112, 100 Hz/8ch −112, 250 Hz −108, 333 Hz/8ch −105, 500 Hz −105 |

Формула:

```text
range% = round(100 * (clamp(rssi, max=-50) + 50) / (minrssi + 50))
```

- Используется RSSI активной антенны.
- RSSI сильнее −50 dBm обрезается до −50 dBm.
- `minrssi` — порог чувствительности для текущего `rf_mode`.
- Значение слегка сглаживается, чтобы не дёргалось.

Важно: **Range — это не расстояние в метрах**, а запас до порога чувствительности. `0 %` — очень сильный сигнал, `100 %` — на пределе линка. Динамическая мощность TX не учитывается: при её росте RSSI увеличивается, а Range% падает.

TX power в CRSF — это enum; вьюер переводит его в мВт: `0→0`, `1→10`, `2→25`, `3→100`, `4→500`, `5→1000`, `6→2000`, `7→250`, `8→50`.


Ключи в `frames` — десятичные значения типов (например, `20` = `0x14`).
В режиме «Сеть» в ответе есть `protocol` (`crsf` или `mavlink`) и `session`.
Для MAVLink `frames` — это msgid, а в `stats` добавляются `messages` и
`messages_pps`; `stats.link_up` считается по свежести `HEARTBEAT`.

`stats.age` — возраст последнего CRSF-кадра любого типа (транспорт). `stats.telemetry_age` — возраст последнего кадра телеметрии с датчиков (без `0x14`), `stats.link_age` — возраст последних link statistics. `stats.link_up` истинно, только если свежие `0x14` имеют `lq > 0` и `lq_d > 0` (как у приемника ESP-NOW). `stats.online` = `link_up` или свежая телеметрия; именно он управляет зелёным индикатором. Кадры `0x14` с `LQ=0` (аппаратура включена, дрон выключен) считаются транспортом, но не связью и не телеметрией.

## USB-приемник ESP-NOW

ESP-NOW-режим использует ESP32-C3 или ESP32-S3 с native USB (например, Super Mini,
DevKitC-1) и USB-OTG на телефоне. Приемник ESP-NOW принимает ESP-NOW от бэкпака и
отдаёт CRSF-кадры в приложение по USB CDC. Разбор протокола — [DESIGN.md](DESIGN.md).

- Прошивки: `esp32-c3-usb-otg` и `esp32-s3-usb-otg` (native USB), PHY BGN.
- Сборка: `./init.sh && ./tools/pio run -d firmware -e <env>`;
  прошивка — `firmware/.pio/build/<env>/firmware.bin`.
- Web Flasher: `webflasher/` + `scripts/make_webflasher.py`; страница
  автоматически определяет ESP32-C3 или ESP32-S3 по чипу. Публикуется workflow
  `.github/workflows/webflasher.yml` на GitHub Pages.
- Подробности сборки и CI — в [DEVELOP.md](../DEVELOP.md).

В настройках приложения (шестерёнка в шапке):

1. включите источник **«ESP-NOW по USB»**;
2. разрешите доступ к USB-приемнику ESP-NOW;
3. задайте **binding phrase** или **ручной UID**, совпадающие с бэкпаком;
4. дождитесь статуса подключения.

После подключения конфиг приемника ESP-NOW читается автоматически. LED:

- не горит — нет связи/пакетов;
- ровный синий — пакеты идут, но линка/телеметрии с дроном нет;
- быстрое мигание — линк живой, телеметрия идёт;
- 3 импульса раз в 2 с — ошибка ESP-NOW или переполнение очереди.

В режиме Wi-Fi USB-приемник ESP-NOW не используется, а в режиме ESP-NOW приложение не
слушает UDP-порт.

## Python-вьюер

Веб-интерфейс для ПК или телефона в браузере. Удобен для разработки и запуска на ноутбуке в поле. Работает с Wi-Fi/UDP. Для USB-приемника ESP-NOW на ПК используйте `tools/serial_bridge.py` и любой CRSF-вьюер; на телефоне — Android-приложение.

1. Включите бэкпак Wi-Fi-телеметрии:
   - ELRS Lua-скрипт на аппаратуре → `Backpack` → `Telemetry` → `WiFi`;
   - не используйте `WiFi Connectivity` — это режим прошивки.
2. Подключите телефон/ПК к той же сети, что и бэкпак:
   - либо к домашней сети/хот-споту, куда бэкпак подключён при прошивке;
   - либо напрямую к точке `ExpressLRS TX Backpack XXXXXX`, пароль `expresslrs`.
3. Запустите вьюер:

   ```bash
   python3 tlm_viewer.py
   ```

4. Откройте `http://localhost:8080` или `http://<ip-компьютера>:8080`.

### Параметры запуска

```bash
python3 tlm_viewer.py --udp-port 14550 --http-host 0.0.0.0 --http-port 8080
```

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `--udp-port` | `14550` | UDP-порт, куда бэкпак шлёт CRSF-телеметрию |
| `--http-host` | `0.0.0.0` | Адрес веб-сервера (`0.0.0.0` — доступен в сети) |
| `--http-port` | `8080` | Порт веб-интерфейса |

### Оффлайн-воспроизведение

Файл записи — JSONL, одна UDP-нагрузка на строку:

```json
{"t": 0.123456, "src": "192.168.0.41:14555", "data": "24583c00..."}
```

- `t` — секунды от начала записи;
- `src` — исходный адрес;
- `data` — полная UDP-нагрузка в hex;
- последняя строка может быть `{"meta": {...}}` — replay её игнорирует.
- `testdata/mavlink_btfl_30s.jsonl` — синтетический MAVLink-поток Betaflight
  (можно пересоздать: `python3 tools/mavlink_sim.py --duration 30 --pos-rate 10 --out ...`).

Тестовые захваты обезличены: координаты перенесены в район Барсово (Сургутский район), исходный адрес источника заменён на условный `192.168.0.41:14555`.

```bash
python3 replay.py testdata/tlm_20261105_111628.jsonl
python3 replay.py testdata/tlm_20261105_111628.jsonl --loop
python3 replay.py testdata/tlm_20261105_111628.jsonl --speed 2
python3 replay.py testdata/tlm_20261105_111628.jsonl --speed 0
python3 replay.py testdata/mavlink_btfl_30s.jsonl --speed 0
python3 replay.py testdata/tlm_20261105_111628.jsonl --host 192.168.1.10 --port 14550
```

По умолчанию пакеты отправляются на `127.0.0.1:14550`. `--speed 0` отправляет всё сразу, `--loop` повторяет запись.

## Диагностика

| Проблема | Что проверить |
|---|---|
| «Нет данных» в режиме «Сеть» | Бэкпак в той же сети; `Telemetry = WiFi`; порт UDP 14550 свободен; firewall |
| «Нет связи с аппаратурой» (USB) | Приемник ESP-NOW подключён по OTG data-кабелем; бэкпак в `Telemetry = ESP-NOW`; приемник ESP-NOW запитан; USB-разрешение выдано |
| «Нет связи с дроном», счётчики растут | Свежие `0x14` с `LQ=0`: дрон/RX выключен, либо не совпадает binding phrase/UID |
| Приемник ESP-NOW не найден | Native-USB ESP32-C3 (VID `0x303A`), OTG-адаптер, data-кабель, разрешение USB |
| Уведомление/индикатор красный при живом дроне | Проверьте `lq`/`lq_d` в карточке «Линк»; при `0` — питание RX и phrase/UID |
| Индикатор зелёный, но GPS/батареи нет | Линк живой, но FC не отдаёт телеметрию или низкий telemetry ratio |
| Бэкпак не поднимает Wi-Fi | Backpack 1.5.7+; для ESP32-C3 — master или workaround `Link Mode = MAVLink` |
| Range показывает `—` | Неизвестный `rf_mode` или режим без известного порога |
| Порт 14550 занят | Остановите другой процесс; вьюер должен быть слушателем |
| После смены порта нет данных | Настройте бэкпак на новый UDP-порт из настроек |
| Не выбирается папка треков | Остановите запись; выберите папку, доступную для записи |
| Живые и записанные данные смешались | Выключите бэкпак перед `replay.py` |
| С телефона не открывается | Порт 8080 в firewall; телефон в той же сети |
| Карта не загружается | Проверьте интернет и доступность OpenFreeMap/Esri/Sentinel; смотрите консоль браузера |
| На карте «Нет GPS-фикса» | У дрона нет GPS-фикса; маркер появится после получения координат |

## Ограничения

- Нет аутентификации: веб-интерфейс и API доступны всем в сети. Используйте доверенную локальную сеть.
- Range-таблица рассчитана на ELRS 4.x; для старых v3 значения `rf_mode` другие.
- Для режимов без табличного порога Range не считается.
- Карта требует интернет. Ключ не нужен; при недоступности OpenFreeMap останется спутниковая подложка, при недоступности Esri — Sentinel-2.
- Выбранная для треков папка должна быть доступна для записи; при смене папки старые треки копируются.
- В Android-приложении точки трека пишутся на каждый GPS-кадр, пока запись активна (включая 2D и отсутствие фикса); в Python-вьюере — только при 3D-фиксе. Незавершённая запись хранится в памяти и сохраняется на диск по кнопке «Стоп» (в Android также по авто-стопу); при подтверждённом закрытии Android-приложения и при падении процесса она теряется.
- Запись новых сессий в репозиторий не встроена; формат JSONL описан выше.
- USB-режим требует native-USB ESP32-C3 и OTG; телефон при этом не заряжается без powered-хаба.
- USB-приемник ESP-NOW отдаёт CRSF; нативный MAVLink доступен только по Wi-Fi.
